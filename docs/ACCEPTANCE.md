# oco 验收矩阵

本文件定义如何证明完成，不代表已有测试。当前全部用例状态为 **NOT RUN**。

## 证据层级

- SOURCE：源码/接口证明入口存在，不证明能在 VS Code 运行。
- BUILD：干净依赖安装、编译、打包等产物检查，不证明 UI 或服务行为。
- UNIT：契约、状态转换、解析和故障夹具通过，不证明实际网络/剪贴板/远程效果。
- INTEGRATION：实际 OpenCode 服务链路通过，不自动证明 VS Code UI 行为。
- UI：实际 VS Code 中完成交互；需记录本地/远端环境和实际服务。

状态使用 PASS、FAIL、NOT RUN、BLOCKED、N/A。N/A 必须说明该能力为何不属于本次发布范围；无法测试不是 N/A。阻断缺口不能因时间到达而被改成 PASS。

每次验收记录：日期、oco 提交、上游 SHA、Server 版本/协议、VS Code 版本、客户端 OS、宿主 OS、本地/远程模式、用例、步骤、结果、证据位置、限制。不能记录密码、token、认证头或真实敏感代码。

## 可靠性夹具

这些属于容易出现真实错误的状态测试，不是逐行重复实现：

1. 重复、乱序、断开的事件流；快照加载期间到达的增量。
2. 面板关闭后响应才回来；面板重新绑定后旧事件才到达。
3. 发送请求成功但响应丢失；不能因此再次执行同一任务。
4. 同时出现多个权限请求；其中一个已由别的客户端回应。
5. 草稿创建会话时身份迁移；并发开两个新草稿。
6. 队列超过容量时触发可观察的重新同步，不能无声丢数据。
7. 配置文件被外部编辑；包含未知字段/JSONC 注释/Markdown 正文。
8. 大小写、空格、非 ASCII 和远程 URI；不能用字符串替换粗糙转换路径。

## 性能验证

P0 先记录官方嵌入基线，T006 根据目标设备固定数值阈值，不在没有测量时虚构“低内存”保证。

至少保存以下数据：

- 第一次打开、已缓存会话重新打开、侧栏切换的耗时分布。
- 一个与三个活跃会话的 Extension Host/Webview 内存和 CPU、服务连接数。
- 十个已打开会话的隐藏/恢复行为；不得依靠保活所有页面才能恢复。
- 长会话（建议使用 500 条混合消息/工具夹具）的滚动和输入响应。
- 连续开关面板 20 次后的订阅、定时器、监听器和内存趋势。
- 流式高频事件时的队列长度、批处理延迟、取消响应和重新同步次数。

明确的最低要求：不能出现持续增长的遗留订阅/进程，不能因其他会话更新而使当前输入丢失或卡死。若仍采用每面板完整 App，必须把成本作为架构限制记录，不能只报告单页面数据。

## 发布阻断项

- 会话串话、错误权限回应、自动重复发送、误杀外部服务。
- 凭据泄漏、消息触发非授权宿主操作、配置或草稿覆盖/丢失。
- 宣称可用的取消、图片、远程、恢复功能缺少真实验证。
- 依赖本机绝对路径、源码目录或运行时 Bun，VSIX 无法独立启动。
- 发布范围内核心流程 FAIL/BLOCKED 且未明确收窄范围。

外部付费服务、远程主机或 Windows 设备缺失时继续能完成的本地验证，并准确写限制；不因此编造 E2E 结果，也不自行新增付费资源。
