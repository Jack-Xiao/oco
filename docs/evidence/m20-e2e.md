## c17-subagent-aggregate (`tests/e2e/c17-subagent-aggregate.mjs`, new; not added to DEFAULT_SUITES)
Setup: an idle session is kept open in the chat panel (it is the sidebar's `selected` session, so a click that wrongly opens another session would change it); the parent is created through the API and sent `Use the read tool on math.ts with offset 1 and limit 2 WITH-SLOW-SIBLING` (the read tool asks no permission; the mock adds one subagent that streams 60 sentences, ~9 s). Required: the first four cases; lazy-children is optional (NOT RUN if VS Code cannot be relaunched; not triggered).
1. badge-running PASS (3 runs): no badge on the parent row before the subagent exists; the badge showed 0.6-2.5 s after the prompt (2462 / 581 / 780 ms), text "0/1", class `running`, aria-label and title "Subagents: 0 done, 1 running", `aria-expanded=false`, list hidden.
2. badge-done PASS (3 runs): after the server was idle (parent and subagent), the badge read "1/1" without the `running` class, label "Subagents: 1 done".
3. expand-collapse PASS (3 runs): clicking the badge showed `.subagents-list` with one `.subagent-row` titled "slow sibling (@explore subagent)" and `aria-expanded=true`; `debugState().selected` stayed on the open idle session and no panel was bound to the parent; a second click gave `aria-expanded=false` and an empty hidden list, selection unchanged.
4. open-child PASS (3 runs): the row's `data-id` equals the child id from `GET /session/:parent/children`; clicking it made `debugState().selected` the child (`openedBy: selected`), not the parent.
5. lazy-children PASS (3 runs): VS Code was closed and relaunched on the same user-data-dir (`fresh: false`) through a recording proxy (`tests/e2e/lib/proxy.mjs`, `intercept` as a request log). The parent row again showed "1/1" (label "Subagents: 1 done", no `running`); the proxy saw exactly 1 `GET /session/<parent>/children` for the parent and 1 roots snapshot (`GET /session?…&roots=true`, which holds roots only), so the badge came from the lazy fetch. In total 74 / 90 / 92 `/children` requests were made at connect (see observation below).
