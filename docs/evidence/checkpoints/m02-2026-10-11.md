# Checkpoint: M02 数据层 (2026-10-11)

## 任务目标与范围
- 目标：M02 数据层——把每个会话的 todo 列表接进 SessionStore 投影，并让 store 记住每个会话最近一次 assistant 消息用的模型（lastModel）。只做数据层，不改侧栏 UI。
- 唯一写入范围：
  - `apps/extension/src/session-feed.ts`
  - `apps/extension/src/session-store.ts`
  - `tests/unit/session-feed.test.ts`
  - `tests/unit/session-store.test.ts`
  - `docs/evidence/checkpoints/m02-2026-10-11.md`
- 禁止改动：`packages/contracts`、`sessions-view.ts`、`sessions-webview.ts`、`media/`、`extension.ts`、`patches`。

## 完成情况与证据
1. `session-store.ts`:
   - 导出 `ServerTodo` 类型 (`{ id: string; content: string; status: TodoStatus; priority?: number }`)。
   - 实现 `setTodo(sessionID, todos)`：整表替换，按 id 去重保序；返回是否有变化。
   - 实现 `hasTodo(sessionID)`、`getTodo(sessionID)`。
   - `applyEvent` 处理 `todo.updated`：整表替换，按 id 去重，返回是否有变化。
   - `applyEvent` 处理 `message.updated`：assistant 消息记录 `{ providerID, modelID }` 至当前会话（子会话不冒泡）。
   - 实现 `lastModel(sessionID)`：返回 `{ providerID: string; modelID: string } | undefined`。
   - `list()` 投影：`todo` 字段按契约投影，`done` = completed + cancelled，`total` = items.length，有数据才填（未获取时为 undefined）。
   - `session.deleted` 与快照裁剪：自动清理 `todo` 和 `lastModel`。
2. `session-feed.ts`:
   - 快照路径完成进入 connected 后，对快照中所有 status 为 busy 的会话懒取 `GET /session/:id/todo`。
   - 实现 `ensureTodo(sessionID: string): void`：同一 epoch 内同一会话只取一次、去重在途请求。
   - 收到 `session.status` 变 busy 且 `!store.hasTodo(sid)` 时自动触发 `ensureTodo` 一次。
   - 并发限制 4：通过队列和并发池 (`SessionFeed.TODO_CONCURRENCY = 4`) 控制。
   - 401 统一转为 unauthorized 状态；404/网络失败记录日志不影响快照与连接。
   - epoch 校验：请求返回前校验当前 token，过期丢弃。
3. 测试与验证：
   - `tests/unit/session-store.test.ts`：追加 2 个针对 todo 去重、替换、投影以及 lastModel 记录、隔离与清理的用例。共 37 用例全部 PASS。
   - `tests/unit/session-feed.test.ts`：追加 7 个针对快照懒取、ensureTodo 去重、session.status 触发、epoch 过期丢弃、404/401 处理与并发上限 4 的用例。共 31 用例全部 PASS。
   - Typecheck：`bun run typecheck` PASS (0 errors)。
   - Unit tests：修改的两个测试文件 68/68 PASS；基线 16 个已提交测试文件 233/233 PASS。
