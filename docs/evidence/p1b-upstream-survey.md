## 1. 主题 / 配色

- 提供者是 Solid `ThemeProvider` / `useTheme()`：`packages/ui/src/theme/context.tsx:12`、`:174-179`。`ColorScheme = "light" | "dark" | "system"`（`:12`）。挂载点 `packages/app/src/app.tsx:402-406`。

  - `opencode-color-scheme`：`"light" | "dark" | "system"`，缺省 `"system"`（`:181`）。
  - `opencode-theme-css-light` / `opencode-theme-css-dark`：非 oc-2 主题的 CSS 缓存（`:140-142`）。oc-2 不写缓存（`:163`）。
- **有 system 模式。** `getSystemMode()` 用 `matchMedia("(prefers-color-scheme: dark)")`（`:128-131`）。`colorScheme === "system"` 时监听 media `change`（`:258-262`）。跨标签 `storage` 事件会改 theme id 和 scheme（`:234-252`）。同一文档里 `localStorage.setItem` **不会**触发 `storage`，所以宿主在应用起来之后改键，不会自动生效。
- 运行时 API 是 `useTheme().setColorScheme(scheme)`：写入 `opencode-color-scheme` 并立刻改 `mode`（`:310-314`）。调用点：`packages/app/src/pages/layout.tsx:350`（system → light → dark 循环）、`settings-general.tsx:472`、`settings-v2/general-controllers.ts:85`。
- `packages/app/src/context/platform.tsx` **没有**配色 API。`embedded`（`:71-73`）只是 oco 单会话宿主标志。`app.tsx:403-404` 的 `onThemeApplied` 只调用 `window.api?.setTitlebar?.({ mode, scheme })`，是桌面标题栏出站，不是嵌入方 setter。
- 另一套更弱的 loader：`packages/ui/src/theme/loader.ts:106-112` 的 `setColorScheme("light"|"dark"|"auto")` 只改 `documentElement` 的 inline `color-scheme`，不持久化。`applyTheme` 仍把 token 放进 `@media (prefers-color-scheme)`（`:32-76`）。从 `theme/index.ts:36` 再导出，**应用不调用它**。活的是 ThemeProvider。
- 首屏脚本 `packages/app/public/oc-theme-preload.js`（`vite.js:41-42` 内联进 `index.html:21`）：读上述两个键，把 `dataset.theme` 和 `dataset.colorScheme` 设成解析后的 `"light"|"dark"`（**不会**写成 `"system"`，`:12-17`），并把 `html` 背景写成实色 `#080808` / `#fafafa`（`:18`）。非 oc-2 再注入 `#oc-theme-preload`。

- 背景 / 前景变量：
  - 旧 token，`packages/ui/src/styles/theme.css:1` 的 `:root`。浅色 `:90-94` `--background-base: #f8f8f8`，`:164-167` `--text-base: #6f6f6f`、`--text-strong: #171717`。暗色在嵌套 `@media (prefers-color-scheme: dark)` `:360-365`（`--background-base: #101010`）、`:438`（`--text-strong`）。
  - v2，`packages/ui/src/v2/styles/theme.css`。`:root` 浅色 `:14-31`：`--v2-background-bg-base`、`--v2-background-bg-deep`、`--v2-text-text-base`、`--v2-text-text-muted`。跟随系统的 `@media` **整段注释掉**（`:147-149`）。显式覆盖是 `[data-color-scheme="light"]` `:261` 与 `[data-color-scheme="dark"]` `:383`（暗色 deep 是 `--v2-grey-1200`，`:387`）。
  - 页面底色：`packages/app/index.html:2` 的 `html` 用 `var(--v2-background-bg-deep, #fafafa)`；`body` 与 `#root` 类名 `bg-v2-background-bg-deep`（`:23-25`）。preload / `applyThemeCss` 随后用实色 hex 覆盖 `html` 的 inline background，所以只改 CSS 变量**不会**重绘 `html` 元素。

- **GET `/global/event`**（`groups/global.ts:36-48`、`GlobalPaths.event` `:70`）。不按实例过滤。总线包装（`bus/global.ts:4-8`，发射处 `event-v2-bridge.ts:39-43`）：`{directory?, project?, workspace?, payload: {id, type, properties}}`。`directory = event.location?.directory ??` 实例上下文目录，可以缺。`server.connected` / `server.heartbeat` 是合成的，只有 `payload`，没有顶层 `directory`，`properties` 为 `{}`。
- 持久事件在 `/global/event` 上还会再发一条 `type: "sync"`，内层 `syncEvent.type` 是 `` `${type}.${version}` ``（`event-v2-bridge.ts:45-59`，`schema/src/event.ts:94-95`）。例如实时 `session.created`，同步副本 `session.created.1`。`/event` 只用无版本的 `type`。`Location.Ref` 是 `{directory, workspaceID?}`（`schema/src/location.ts:8-12`）。
- 事件名与 `properties`（运行中的服务用 v1；`schema/src/permission.ts:43` 的 `permission.v2.asked` 和 `schema/src/question.ts:70` 的 `question.v2.asked` **不是**这条服务在发的名字）：
  - `session.created` / `session.updated` / `session.deleted`：`{sessionID, info}`，`info` 含 `directory`。durable，aggregate `"sessionID"`，version 1（`schema/src/v1/session.ts:502-507`、`:572-594`）。创建发布点 `session/session.ts:535`。
  - `session.status`：`{sessionID, status}`；转入 idle 时另发 `session.idle`：`{sessionID}`（`session/status.ts:41-44`，schema `session-status-event.ts:35-48`）。不 durable。`session.idle` 标了 deprecated（`:43`）。
  - `session.error`：`{sessionID?, error}`（`v1/session.ts:651-657`）。不 durable。发布点 `session/prompt.ts`（例如 `:318`）。`error` 形如 `{name, data}`（`namedError`，`:29-34`）。`name` 联合 `:385-394`：`ProviderAuthError{providerID,message}`、`UnknownError{message,ref?}`、`MessageOutputLengthError{}`、`MessageAbortedError{message}`、`StructuredOutputError{message,retries}`、`ContextOverflowError{message,responseBody?}`、`ContentFilterError{message}`、`APIError{message,statusCode?,isRetryable,responseHeaders?,responseBody?,metadata?}`。
  - `permission.asked`：properties 就是 Request 各字段（`permission/index.ts:10`、`:100`）。`permission.replied`：`{sessionID, requestID, reply}`（`:115-119`，schema `v1/permission.ts:61-65`）。`reject` 会把同会话其它 pending 也以 `reply:"reject"` 回掉（`:129-137`）；`always` 会自动以 `reply:"always"` 回掉匹配项（`:153-165`）。不 durable。没有 `permission.updated`；同一 id 再来一次 `permission.asked` 才是更新。
  - `question.asked`：Request（`question/index.ts:25` 导出 `QuestionV1.Event`，发布 `:104`）。`question.replied`：`{sessionID, requestID, answers}`（`:126-130`）。`question.rejected`：`{sessionID, requestID}`（`:143-146`）。schema `v1/question.ts:58-60`。不 durable。

## 对 oco 的建议

- 跟宿主亮暗：加载前写 `opencode-color-scheme`（`"light"|"dark"`，不要指望 iframe 的 `prefers-color-scheme` 跟随父页面 class）。要对齐宿主色板，改 v2 变量的同时改掉 `html` 的 inline background。没有 Platform hook 可在运行时从外面设。
- 不要用 `sync().ready()` 或 `status === "complete"` 当提交门闩。门闩是 `agent.current()` 与对目录目录有效的 `model.current()`。`model.loading === false` 且模型控件不再显示 “Select model” 才接近可提交；最稳是在嵌入层等到 `provider_ready` 且 `agent.length > 0` 再启用发送。
- 权限/问题页脚：v1.18.33 的不换行来自 footer / footer-actions 的 flex 默认 nowrap，加上 `button` 的 `white-space: nowrap` 和托盘 `overflow: clip`。工作区 `message-part.css` 已有未提交的 wrap 补丁；若仍裁切，再改按钮的 nowrap、固定 `height` 和托盘的 `overflow: clip`，不要把 nowrap 加回去。
- 侧栏列表用 `GET /session?directory=<dir>&roots=true&limit=`，不要只靠 `x-opencode-directory`（头只选实例，不过滤同 project 的其它目录）。空闲状态看 `GET /session/status` 里**没有**该 id，外加 SSE `session.status` / `session.idle`。实时更新订 `GET /event?directory=`（或头），读 `data.type`，不要读 SSE 的 `event` 名（恒为 `message`）。权限和问题用 v1 事件名，忽略 `*.v2.*`。`/global/event` 的持久事件会再来一条 `sync` / `session.created.1`，侧栏若只处理无版本 `type` 就不要重复插入。
