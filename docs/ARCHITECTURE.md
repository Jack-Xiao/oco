# oco 架构与边界

状态：设计候选。所有拟议模块、接口和目录均未实现；P0 后通过 ADR 固定具体做法。

## 1. 进程划分

```text
VS Code 客户端
  ├─ 原生侧栏：Sessions / Agents
  ├─ 编辑器：会话 A Webview / 会话 B Webview / 管理页
  └─ 原生编辑器：文件 / Diff / 配置源文件
             │ 有类型的消息协议与 VS Code API
Extension Host（本地工作区在本机；Remote-SSH 工作区在远端）
  ├─ Connection Manager：连接、认证、能力与所有权
  ├─ Session/Event Coordinator：身份、事件、恢复、取消
  ├─ Panel Registry：面板身份、恢复和路由
  ├─ Editor Context / Diff / Agent Config
  └─ OpenCode 适配层：真实 API、流、可选其他传输
             │ 经验证的服务契约
OpenCode Server：会话、执行、模型、工具、权限及工作区操作
```

一个 VS Code 窗口可有多个会话面板；不要为每个面板启动一个 Server。

P0 优先验证“宿主持有网络连接，Webview 走消息桥”。如果官方 UI 难以适配而使用直连转发 URL，必须在 ADR 写明认证、origin、CSP、SSE、WebSocket 和重连方案，不能混用两种方式而没有所有权定义。

## 2. 拟议代码组织

```text
apps/extension/src/
  extension.ts
  connections/          # 连接、自有进程、健康和能力
  sessions/             # 会话查询、事件协调、取消
  panels/               # 生命周期、身份、消息分发
  views/                # 原生 TreeView
  editor/               # 选区、未保存文档、文件和 Diff
  agents/               # 配置解析、来源、写回和生效验证
  settings/             # 扩展设置
  diagnostics/          # 脱敏日志
apps/chat-webview/       # 官方对话的嵌入入口、布局和宿主桥
apps/management-webview/ # Agent 表单及复杂管理页
packages/contracts/     # 消息协议和内部领域类型
packages/opencode-adapter/ # 目标服务和官方 UI 传输适配
vendor/opencode/        # 经决定后的固定上游源码，不复用邻近工作目录
patches/opencode/       # 可重复应用的上游修改
tests/{unit,integration,fixtures,e2e}/
docs/{adr,evidence}/
```

T003 可以因上游 workspace 约束调整物理目录；调整后同步任务归属，不能只改代码不改计划。引入源码的方式（submodule、固定提交快照等）由 ADR-002 记录；必须包含许可证、精确 SHA、恢复步骤和依赖锁文件。

## 3. 服务连接与进程所有权

两种连接类型：

- `attached`：用户提供的现有服务。扩展只连接；停用扩展、关闭窗口、断线和切换工作区都不能终止它。
- `managed`：由扩展启动的进程。记录启动参数、PID/所有权标识、监听地址及生命周期；只清理可以证明属于本扩展的进程。

默认先支持 attached。managed 使用受支持的可执行文件和临时认证，绑定适当的回环地址；不把随机发现的端口或进程当成自己的服务。绝不因为固定端口被占用而杀掉占用者。

连接身份使用持久化的 `connectionId`。转发 URL、随机端口和本次启动密码不是稳定身份。认证放入 VS Code SecretStorage，非秘密元数据放入扩展存储；不能把密码放进持久化 URL、日志、前端包或会话恢复数据。

Server 能力来自实际健康信息、OpenAPI、有限的无破坏探测和已验证兼容表；不只依赖版本字符串，也不使用模糊版本判断承诺未知接口。

## 4. 状态归属

| 状态 | 事实来源 / 存储 | 说明 |
| --- | --- | --- |
| 会话消息、运行状态、工具结果 | OpenCode Server | 本地缓存不能覆盖服务端事实 |
| 选中的模型和 Agent | 按实际服务与 UI 语义分开记录 | 区分默认偏好与会话实际使用值 |
| 面板恢复 | Webview state + 宿主 registry | 只存恢复所需身份与少量视图信息，不存凭据 |
| 草稿和附件草稿 | 受控 DraftStore，按会话/新建草稿隔离 | 关闭、重开、重载的语义必须一致；附件设容量与清理策略 |
| 展开状态、排序、UI 偏好 | workspace/global storage，明确作用域 | 不依赖服务随机端口的 localStorage origin |
| Agent 配置 | 实际服务所在环境的官方配置源 | 展示来源、优先级和有效配置 |
| 连接秘密 | SecretStorage | 不广播到各 Webview |

会话面板建议身份：`connectionId + 规范化的项目/目录身份 + sessionId`；实际服务若有稳定 projectId 则优先使用。路径规范化必须考虑远端 URI、大小写和平台，不简单拼接本地字符串。

新会话未获得 sessionId 时使用独立 draftId；创建成功后原子绑定会话身份，避免两个草稿串写。

## 5. 对话源码复用

分两步：

1. P0 用最小入口挂载官方 App，确认真实构建和运行限制。
2. P1 收敛成单会话嵌入模式：由 VS Code 控制会话路由，关闭内部多标签/服务器切换/不支持的应用入口；保留聊天所需 provider。

不要一开始拆散所有官方状态提供器，也不要仅通过 CSS 隐藏导航就认为完成嵌入。必须处理仍然活跃的全局快捷键、通知、默认导航和持久化。

建议新增的小范围宿主接口（设计要求，不是官方现成接口）：

- 绑定当前会话及工作区。
- 向指定草稿添加代码或附件，不自动发送。
- 请求 VS Code 打开文件、位置和 Diff。
- 上报标题、未发送状态和当前会话身份。

每次上游修改需记录目的、文件、原因、替代 API 是否存在、回归用例和基线 SHA。升级先重放补丁及用例，再更新依赖；不能边做功能边自动跟随 upstream 最新提交。

## 6. 宿主桥与流式传输

公共消息信封至少包含：协议版本、消息类型、requestId、面板身份、会话身份、载荷。协议需有运行时校验，不能只依赖 TypeScript 编译期类型。

生命周期至少覆盖：ready/初始化、请求与响应、事件、取消、错误、恢复、dispose。每次面板恢复或重新绑定产生新的 epoch，丢弃旧请求迟到的响应。

关键约束：

- Webview 与 Extension Host 之间不能直接传递函数、原生 Response 或 ReadableStream；需要以可序列化消息重建相应语义。
- fetch 适配必须处理请求体、状态码、响应头、文本/二进制、分块、AbortSignal 和错误；SSE 必须验证增量与取消，不得把整条响应缓冲到结束才显示。
- WebSocket 不由 fetch 自动覆盖。T002 枚举路径；v0.1 禁用的终端功能不应建立悬空连接，保留功能需要的其他路径必须实现。
- 官方 UI 的业务 schema 仍耦合其 SDK；传输替换不能被描述为“所有 v1/v2 差异已隔离”。
- 优先由宿主每连接维护受控事件订阅并路由到相关面板；这是目标架构，须确认官方同步层能接入。P0 若暂时每面板独立订阅，记录连接数、负载和去重行为，不能标成共享订阅已实现。
- 慢面板需要有界队列/批处理；溢出时明确标记需要重新同步，而不是静默丢事件。
- 重连没有服务端游标时，重新拉取会话快照并协调后续事件；避免快照与事件窗口竞态、重复消息和顺序错乱。不能假设本地递增序号等于服务端重放能力。
- 网络错误不能无条件重发有副作用的发送请求；先查询是否已创建消息，无法确定则显示“发送结果未知”，让用户决定重试。
- 桥只暴露受控业务操作或限定目标的传输能力，不接收任意 URL、任意 shell 或任意文件读取命令。

## 7. 编辑器上下文、附件与 Diff

“加入对话”传递文档 URI、展示路径、语言、选择范围、实际内容及版本/时间信息。未保存内容来自 `TextDocument`，不能只给服务器一个路径。

加入草稿后不自动随编辑器变化替换内容；用户能移除或重新添加。向哪个会话添加必须可见；不能默默使用后台最后活跃会话。

本机选取/粘贴附件、远端工作区文件、编辑器未保存文档是三种不同来源。通过实际读取与协议转换传递字节，校验 MIME/大小和编码；不能把本机绝对路径当成远端可访问文件。产品 UI 显示可理解的附件名称、大小和失败原因。

Diff 必须有真实 base/head 内容及来源。区分会话改动、当前工作区改动、单次工具改动。若服务只有路径/统计而缺少前像，回退为打开文件或 Git diff，并明确差异来源；不得构造“原文件”误导用户。

v0.1 只负责展示可验证的差异，不擅自实现可能覆盖后续编辑的回滚/接受修改。

## 8. Agent 与设置

Agent 定义管理与运行中的 Agent/子任务监控是两种能力。v0.1 做前者，运行状态通过会话展示；不引入新调度器。

对每个 Agent 展示来源范围、文件/配置位置、是否内置/只读/被覆盖。写回原格式和原作用域，保留未知字段、JSONC 注释、Markdown 正文及 frontmatter。写入前检查文件版本或 hash，发现外部修改不能直接覆盖。

若连接的服务不在 Extension Host 可访问的文件系统中，使用经证实的服务配置写入 API；没有该能力就明确只读，不能写本地同名路径冒充远端保存成功。

保存后读取有效配置或执行经验证的刷新方式。需要重启时显示待生效状态；不得自行重启 attached 服务。设置变更不自动影响已运行任务，具体生效范围依据目标服务验证。

连接配置与 UI 偏好优先用 VS Code Settings；复杂 Agent 管理单独页面。避免建立与 OpenCode 官方配置竞争的第二套模型/provider/权限数据库。

## 9. 远程和安全边界

- Remote-SSH 时工作区逻辑在远端宿主；Webview 在本机客户端，不把 localhost 视为同一机器。
- 静态资源通过 `asWebviewUri`；网络若使用转发必须使用 `asExternalUri` 返回的完整 URI，并在重连后重新解析，不永久缓存。
- 自建进程启动和写配置遵守 Workspace Trust；不受信任工作区不自动启动执行服务或更改配置，显示可操作的受限状态。
- Webview 采用有限 CSP、资源白名单和输入校验；对话中的代码/HTML/链接是数据，不能直接成为宿主命令。
- 权限判定仍由 Server 完成；允许/拒绝按钮必须绑定正确请求和会话，过期请求不可误提交到新任务。
- 日志输出连接身份与操作状态即可；避免认证头、URL token、消息全文和图片字节。

## 10. 必须形成的 ADR

- ADR-001：实际服务/协议契约、支持版本与环境范围。
- ADR-002：上游 SHA、源码引入、工具链、嵌入模式、补丁与升级策略。
- ADR-003：传输路径、SSE/取消/恢复、事件共享、资源与认证边界。
- ADR-004：P0 结论、继续/修正路线、重新估算及未验证项。

ADR 由实际实验产生，不能在计划阶段写成“已验证”。
