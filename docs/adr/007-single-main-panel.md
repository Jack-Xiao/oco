# ADR-007：面板保持存活与单主面板会话切换

状态：第 1 步已采纳；第 2–4 步为设计，待实测后实施。日期：2026-09-30。修订 [ADR-005](005-p1a-identity-storage-connection.md) 第 1、2、6 节。

## 背景

用户反馈：点会话就开一个新 webview，而且每次切换编辑器 tab 回来都要重新加载。原因是面板用 `retainContextWhenHidden:false`，隐藏时文档被销毁，再显示时重新走一遍冷启动（加载包、桥握手、会话同步）。另外，每个会话固定占一个编辑器 tab。

## 决定

目标体验：日常只用一个**主面板**，点侧栏会话时在主面板内切换；需要对比时，用"在新面板打开"开一个**独立面板**，它固定显示一个会话。所有面板隐藏时都保持存活。

### 第 1 步：面板保持存活（已实施）

- `createWebviewPanel` 改为 `retainContextWhenHidden:true`。隐藏不再 retire generation，也不关闭事件流；草稿在面板再次可见时投递。
- `retire()` 只在页面重载（新 `hello`）和面板关闭时发生。
- 代价：每个打开的面板常驻一份 app 内存。单主面板模式下，常驻的面板数就是 1 加上独立面板数。
- E2E：`p1a-identity` 的 `hide-retires-generation` 改为 `hide-keeps-document`（隐藏与再显示时 generation 不变，未发送的草稿仍在）。

### 第 2 步：实测（证据门槛）

在嵌入模式下由宿主驱动 app 内切换会话，分别测同目录和跨目录两种情况：切换耗时、消息与草稿是否串会话、事件流是否保持。结果写入 `docs/evidence/`，决定跨目录走 app 内切换还是重载文档。

### 第 3 步：身份模型（设计）

- 面板角色：`main`（最多一个，跟随侧栏）和 `pinned`（固定一个会话）。面板身份改为 connectionId + 面板 id；"当前会话"是可变状态，只由宿主改动。
- 切换由宿主说了算：页面内要去别的会话，仍发 `openSession`；宿主校验（同连接、属于当前工作区）后，更新该面板的当前会话（bridge-policy 允许有副作用操作的会话集合跟着变），再给页面发 `navigate{sessionId, directory}`；页面路由守卫只接受宿主最后下发的会话。需要改公共契约。
- 点击会话的去向，按顺序：已在某个面板显示的，聚焦那个面板；否则主面板切过去；没有主面板就新建一个。
- 按会话处理的状态：待插入草稿改为按 sessionId 存；插入到未显示的会话时，先让主面板切过去。标题和侧栏的"已打开"标记跟随当前会话。
- 恢复：`setState` 保存面板角色和当前会话；Reload Window 后角色不变。
- 补丁 0002 不放开上游自带的标签栏、home 和新建窗口。会话切换统一由宿主驱动。

### 第 4 步：侧栏

点击走上面的去向规则；右键菜单加"在新面板打开"。E2E 要覆盖三点：切换后发消息只落在新会话；独立面板不受侧栏点击影响；切换过程中草稿不串会话。

## 不做

- 不用"宿主重设 HTML、换一个会话绑定"的方式切换：那仍是冷启动。
- 暂不限制常驻面板数（LRU）。等内存确实成为问题再做。
