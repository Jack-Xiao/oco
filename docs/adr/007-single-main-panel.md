# ADR-007：面板保持存活与单主面板会话切换

状态：第 1 步已采纳（`fe20a44`）；第 2–4 步已实施，待提交。日期：2026-09-30。修订 [ADR-005](005-p1a-identity-storage-connection.md) 第 1、2、6 节。

## 背景

用户反馈：点会话就开一个新 webview，而且每次切换编辑器 tab 回来都要重新加载。原因是面板用 `retainContextWhenHidden:false`，隐藏时文档被销毁，再显示时重新走一遍冷启动（加载包、桥握手、会话同步）。另外，每个会话固定占一个编辑器 tab。

## 决定

目标体验：日常只用一个**主面板**，点侧栏会话时在主面板内切换；需要对比时，用"在新面板打开"开一个**独立面板**，它固定显示一个会话。所有面板隐藏时都保持存活。

### 第 1 步：面板保持存活（已实施）

- `createWebviewPanel` 改为 `retainContextWhenHidden:true`。隐藏不再 retire generation，也不关闭事件流；草稿在面板再次可见时投递。
- `retire()` 只在页面重载（新 `hello`）和面板关闭时发生。
- 代价：每个打开的面板常驻一份 app 内存。单主面板模式下，常驻的面板数就是 1 加上独立面板数。
- E2E：`p1a-identity` 的 `hide-retires-generation` 改为 `hide-keeps-document`（隐藏与再显示时 generation 不变，未发送的草稿仍在）。

### 第 2 步：实测（证据门槛）— 已完成

E2E `p1b-main-panel`（mock 模型，本机）测得：同目录面板内切换 270–400 ms（从执行命令面板命令算起，包含 quick pick 操作）；新开面板（冷启动）2477 ms。切换后发送只落在新会话，草稿不串，generation 不变（没有重载）。

路由里只有会话 id，不带目录，所以页面本身不限制跨目录切换。限制目录的是 bridge-policy：它把所有请求都钉在一个目录上。结论：
- 同目录走面板内切换。
- 跨目录重建桥并重载文档，这属于少见路径：VS Code 工作区通常只有一个目录，侧栏也只列当前工作区目录的会话。这条路径没有专门的 E2E。

### 第 3 步：身份模型（已实施）

- 面板角色：`main`（最多一个，跟随侧栏）和 `pinned`（固定一个会话）。注册表按面板 id 索引；"当前会话"是可变状态，只由宿主改动。`WebviewInit.role` 让页面把角色存进 `setState`，恢复时读回；如果恢复出第二个 main，就降为 pinned。
- "新建会话"也在主面板打开。页面里的会话链接：主面板在原地切换；固定面板里点的链接交给主面板打开。
- 切换由宿主说了算：页面内要去别的会话，仍发 `openSession`；宿主校验（同连接、属于当前工作区）后，更新该面板的当前会话（bridge-policy 允许有副作用操作的会话集合跟着变），再给页面发 `navigate{sessionId}`（契约新增 `Navigate`、`PanelRole`、`WebviewInit.role`）；页面路由守卫只接受宿主最后下发的会话。
- 点击会话的去向，按顺序：已在某个面板显示的，聚焦那个面板；否则主面板切过去；没有主面板就新建一个。
- 按会话处理的状态：待插入草稿的队列键按当前会话计算（`PanelRegistry.panelKey(binding)`），切回该会话时再投递。"加入草稿"命令只列出当前正在显示的会话。标题和侧栏的"已打开"标记跟随当前会话。面板级存储命名空间（`opencode.window.*`）在面板生命周期内固定。
- 切换后宿主把 `ready` 置为 false；页面渲染出新路由后再报 `ready`，宿主据此投递草稿。晚到的、属于旧会话的 `ready` 被忽略。
- 恢复：`setState` 保存面板角色和当前会话；Reload Window 后角色不变。
- 补丁 0002 不放开上游自带的标签栏、home 和新建窗口。会话切换统一由宿主驱动。

### 第 4 步：侧栏（已实施）

点击走上面的去向规则；右键菜单和命令面板加 `oco: Open in New Panel`。E2E `p1b-main-panel` 覆盖六点：原地切换、切换后发送只落在新会话、草稿按会话、固定面板不受影响、已显示的会话只聚焦、重载后角色不变。

## 不做

- 不用"宿主重设 HTML、换一个会话绑定"的方式切换：那仍是冷启动。
- 暂不限制常驻面板数（LRU）。等内存确实成为问题再做。
