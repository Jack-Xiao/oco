## 3. P1a 范围与顺序

### P1a-00：先让测试能够判错

- 修复统一测试入口；建立所需的身份/存储/桥状态测试，而不是创建空测试让命令变绿。
- 确保断言失败、必需测试未执行和异常退出均产生明确非零状态，保留结构化结果。
- 为流式、答案、重载、关闭标签和多会话重写上述薄弱断言；用一条故意错误的预期或可控负向夹具证明测试会失败，然后恢复正常断言。
- 失败截图、成功截图与结果用 runId 隔离；记录产品提交、上游 SHA、测试脚本版本和运行环境。
- 增加请求重挂载负向夹具：旧 SSE 未结束时创建新文档、复用序号，证明旧 chunk/finally/abort 不可影响新请求。构建只读代理不能写产物时改交可写测试代理，不将环境权限失败记成代码失败。

本项先固定测试契约和退出规则；针对缺陷的回归可先是红色，随后由 P1a-01～03 修复。不要为了先得到全绿而绕过真实缺陷。

### P1a-01：固定面板身份（T010 提前子任务）

目标：一个 VS Code 会话标签始终对应绑定的连接、项目和 session，或者通过明确的宿主操作打开/切换到另一个面板。

- 用可维护的官方源码嵌入入口收敛内部 tabs、服务器切换、会话导航、全局快捷键和持久化恢复。只用 CSS 隐藏标签栏不足以保证身份正确。
- 面板 registry、Webview 路由、草稿目标、标题、当前模型/Agent 展示和权限请求归属保持一致。
- 对子会话/文件等仍需跳转的入口定义宿主操作；不能留下能静默改变面板会话身份的路径。
- 显式禁用本版本不支持的终端入口和自动恢复路径，防止创建未适配的 WebSocket。
- 宿主不能完全信任页面声称的 session/directory。对具有副作用的当前会话操作校验绑定关系；列表读取与合法子会话行为应单独定义，避免一刀切破坏官方同步。
- 为每个实际 Webview 文档建立唯一 generation；请求捕获创建时的 generation/controller，旧响应不可改盖新 generation。销毁/隐藏重建时释放旧订阅；同 id 替换及 finally 清理使用身份比较，不能误删新请求。具体通过握手还是重新 render 实现由集成人决定。

验收：通过内部导航、快捷键、深链接和旧持久化 tabs 尝试切换到其他 session；结果必须是被禁用、返回绑定会话，或交给宿主打开正确面板。操作后加入选区、发送、停止、回应权限，不能作用于错误会话。

### P1a-02：并发存储与恢复（T008/T010 的正确性前置）

- 划分用户偏好、工作区状态、连接状态、会话草稿和面板临时状态的命名空间。
- 解决整表快照写回造成的覆盖；逐 key 操作仍需考虑同 key 并发、异步写入顺序和陈旧面板，必要时使用版本或宿主串行处理。
- 区分已证实的提前成功确认/错误处理缺失与尚未复现的并发丢写风险；先用实际 VS Code Memento 语义或忠实模拟写出反例，不凭整表更新形式推定所有写入必然丢失。
- 明确 web 平台下哪些官方状态仍使用 localStorage。不要为了接管存储而简单伪装为 desktop，触发未经验证的桌面分支。
- 稳定身份基于 connection/project/session；随机端口和虚拟 URL 不能是唯一隔离键。
- 恢复、初始化默认值、旧 epoch 的迟到保存不得覆盖更新的草稿。
- 迁移现有 P0 数据须保留可恢复副本或安全读取路径；不能通过清空状态让测试变绿。

验收：两个页面从相同旧快照分别写不同 key，两个结果均保留；同 key 的乱序提交按约定解决；三会话同时可见并发编辑、隐藏恢复、Reload Window 后仍无覆盖。

### P1a-03：连接边界（T007 最小前置）

- 先完善 attached 模式：稳定 connectionId、目录归属、凭据作用域、错误状态和 Workspace Trust；不要在状态尚未隔离时先增加大量 managed 进程功能。
- 服务地址由明确的用户连接配置决定，不能让仓库级设置静默替换凭据目的地；秘密按可信连接/规范化服务身份隔离，端点变化时不得沿用旧认证。校验协议、认证转发与重定向。保留合法的显式远程服务配置能力，不因原型使用回环地址就永久禁止所有非回环服务。
- 使用经过验证的目标服务目录语义，统一处理 query、目录 header 和其他路由覆盖入口。只有目录确实在当前宿主文件系统时才做本地 realpath；远程服务路径不能盲目映射为本机路径。
- 桥的可信范围需要有明确决定：origin 限制只防任意目标网络地址，不等于会话权限限制；校验具有副作用的资源与操作。
- 对取消、关闭面板、宿主重载分别定义语义，保留“关闭面板不等于停止任务”。
- 限定测试/开发命令及配置在生产版本的可用范围；不将开发辅助能力视为正式功能。

验收：不同连接即使具有相同 sessionId/目录名也不混淆；非法/过期桥消息不可作用于新会话；受限工作区不能通过旁路执行服务操作；外部服务始终不被扩展终止。

执行顺序：P1a-00 建立可靠判错 → P1a-01 的 generation/请求生命周期与 P1a-03 的目的地/目录约束 → P1a-01 的单会话路由与 P1a-02 存储 → P1a-04 全批验收。先固定 identity/storage/bridge 契约，再分配写入任务；修改同一宿主文件时由集成人串行整合，不强行并行。

### P1a-04：补齐回归并修正文档

- 保留现有流式、工具、权限、提问、取消、图片、恢复用例，增加上述攻击性导航和并发状态用例。
- “三个编辑器标签页打开”与“三个 Webview 同时可见且并发运行”分别记录；后者至少使用三个 editor group 验证一次。
- 真实 macOS 剪贴板图片与中文输入法单列。合成 ClipboardEvent 的字节测试不等于系统剪贴板通过。
- 性能测量记录可见页面数、进程归属与方法；先消除订阅泄漏/错误恢复，不因单次内存差值直接重写官方 UI。
- 更新 ADR-004 的门槛 3、PROGRESS 的阶段结论与 HANDOFF；旧记录保持历史含义，新用例必须有当前版本证据。
