# oco 开发计划

计划日期：2026-09-29。状态：P0 完成（本地验证通过，远程 BLOCKED），进入 P1。

## 1. 产品目标

让用户在 VS Code 内完成 OpenCode 的日常工作：找到项目会话、打开多个对话、加入编辑器上下文、审查改动、管理 Agent 和常用配置。

用户已明确的需求：

- 左侧会话列表和 Agent 管理入口。
- 会话在编辑器区域以独立标签页打开，允许同时打开多个。
- 独立的设置与管理体验。
- 复用 OpenCode 能力，同时可以扩展官方 Web 目前不足的功能。
- 项目名称和目标目录是 `oco`、`/Users/xiaojiang/Ai-Project/oco`。

本计划的默认假设：面向内部团队，优先桌面版 VS Code；先验证 OpenCode v1 兼容目标；保留 Remote-SSH 到 Linux 工作区的能力。团队实际服务版本、企业修改和客户端系统分布在 T001 确认。

## 2. 首个交付版本 v0.1

### 必须完成

| 区域 | v0.1 行为 |
| --- | --- |
| 连接 | 连接已有服务；明确显示连接状态、目标服务、工作区与版本；支持经过验证的认证方式 |
| 本地启动 | 可选择启动指定路径的 OpenCode；只有自有进程由扩展管理；不自动安装或升级 OpenCode |
| 会话列表 | 按连接和工作区展示会话；创建、搜索、刷新、重命名；状态与服务同步；点选打开或聚焦已有标签页 |
| 对话 | 复用官方输入和渲染能力；文本、流式回复、工具状态、权限/提问交互、模型/Agent 选择、已支持命令、附件、取消和恢复 |
| 多标签页 | 会话身份明确；各自草稿隔离；隐藏/恢复/重载不串话；关闭标签页不自动终止任务 |
| 编辑器上下文 | 选中代码或当前文件加入指定会话草稿；包含未保存内容、文件来源和范围；由用户发送 |
| 文件和 Diff | 点击文件引用打开正确位置；明确是本轮/会话/工作区哪一种改动；只展示有可靠快照的 Diff |
| Agent | 展示来源和有效配置；创建、复制、编辑；项目/用户范围明确；提供原始文件编辑入口 |
| 设置 | 连接、可执行文件、UI 偏好；常用 Agent 配置管理；显示更改生效状态 |
| 分发 | 可复现构建、可安装 VSIX、安装/连接/故障说明、脱敏诊断输出 |

“复用官方”不等于承诺完整 Web 功能一比一兼容。T002 必须产出功能清单，标明保留、宿主接管、明确禁用的入口。不能留会报错的按钮冒充支持。

### v0.1 不做

- 自建 Agent 推理循环、工具执行系统、权限判定系统。
- 定时任务、多模型同时竞赛、自治多 Agent 调度、团队账号与 RBAC。
- 完整内置终端/PTY、完整官方设置页镜像、官方全部导航功能。
- VS Code 浏览器版、Codespaces Web、Cursor/Windsurf 等分支的兼容承诺。
- 自动更新 OpenCode、自动迁移 v2、扩展自建下载更新器。
- 无基线证据的细粒度“接受/拒绝此块改动”、伪造修改前快照。

v0.1 不要求终端 UI；如果官方对话的导入依赖终端模块，必须隔离、禁用对应入口或正确适配，不能因为不测试而留下运行时故障。

## 3. 首选技术路线

- Extension Host：TypeScript，使用 VS Code 提供的 Node 运行时。
- 左侧简单列表：原生 TreeView；管理复杂表单及对话：Webview。
- 对话：固定官方源码基线，保留必要的状态提供器，增加嵌入入口。P0 可先挂完整 App 证明路径，P1 收敛为受控单会话视图。
- 构建：优先使用与选定官方源码兼容的 Bun/Vite/SolidJS 工具链。Bun 是开发构建依赖，不得成为扩展运行时必需项。具体版本和工作区方式由 T003 实验后锁定。
- 测试：宿主/契约测试优先选 Vitest；真实 VS Code Extension Host 测试工具在 T003 固定；需要原生编辑器/远程/剪贴板的项目保留人工或 UI 自动化验收。
- 通信：优先经 Extension Host 连接服务器、持有凭据，向 Webview 提供有类型的消息桥；官方网络层的适配必须实际验证。
- 源码来源：候选为官方 `v1.18.33`，不是已确认兼容版本。T001/T002 共同确定精确 SHA 和测试服务版本。

这是一项候选选择，不声称平台 fetch 已覆盖所有网络路径，不声称未来跨代升级只改连接层。

## 4. 阶段及门槛

### P0：可行性验证（建议限时 3–5 人天）

顺序：T001/T002 → T003 → T004 → T005 → T006。

交付：固定源码与服务证据、最小扩展、真实聊天原型、三会话原型、初步远程连接结果、架构决定记录。

必须证明：

1. 官方源码可以复现构建并在 Webview 中运行，资源/Worker/CSP 没有阻断核心对话。
2. 文本流、一次工具操作、权限回应、真实服务端取消可以走通；问题交互若测试模型不触发，使用协议夹具补测并标注真实覆盖缺口。
3. 三个会话同时打开，身份、草稿、回复和权限归属正确。
4. 选中代码加入指定会话草稿；文本和图片输入至少各完成一次真实链路验证。
5. 不在 Webview 中放入长期凭据；重载可恢复会话；关闭页面不会误杀外部服务。
6. 对承诺的 Remote-SSH 目标完成连通和流式原型；若环境不可用，明确远程能力仍未验证。

P0 通过后进入 P1。若仅远程环境暂缺，可以继续本地 P1，但不得宣称 P0 的远程门槛或远程发布验收已通过。

限时到达不等于成功，也不自动宣布放弃。T006 记录实际障碍和剩余工作，然后选择：

- **继续首选路线**：补丁集中在宿主适配、布局与明确入口，核心状态保持可理解且可维护。
- **有限延长实验**：有明确故障和修复路径，记录额外范围与估算，不无期限探索。
- **替代路线**：若多会话隔离或官方内部依赖需要广泛重写，评估复用已有客户端或自研精简会话视图，更新 ADR、任务和估算。iframe 仅保留为临时外部界面入口，不作为注入式长期方案。

### P1：可用的会话客户端（约 9–13 人天，P0 后重估，见 ADR-004）

T007–T012；完成连接、状态、列表、多标签页、编辑器上下文、Diff。

门槛：真实工作区可完成“创建会话 → 添加代码 → 发送 → 工具/权限 → 查看改动 → 中止或完成 → 恢复”的闭环；不依赖手动打开浏览器或改 DOM。

### P2：管理能力和团队体验（约 5–8 人天）

T013–T015；完成 Agent 管理、设置、可理解的错误与诊断。

门槛：配置来源可见、写回正确位置、未覆盖未知字段和注释、有效配置可验证；不通过重启共享服务“解决”所有问题。

### P3：远程、多平台与交付（约 7–12 人天）

T016–T019；完成环境矩阵、恢复和性能验证、可复现打包与发布候选验收。

门槛：ACCEPTANCE 中要求的用例有记录；发布范围内无阻断项；构建产物可安装。

## 5. 时间预算的使用方式

P0 后重估总投入为 **24–38 人天**（原 23–37），约单人 5–8 个工作周，不包含缺失环境、企业协议改造和重大上游兼容问题的等待时间。这是规划预算，不是交付承诺。

P0 后必须重估。多 AI 可以并行实现独立模块，但公共契约、官方 UI 嵌入和集成仍在关键路径上，不能把总人天简单除以 AI 数量。

## 7. 排期外的未决事项

真实服务版本与定制、测试账号/网关、远程环境、Windows 优先级、扩展 publisher 和分发渠道均列在 EVIDENCE。实施者先检查可获取的环境信息；只有影响后续正确性而无法自行确认的部分才询问用户，不重复确认已确定的产品形态。
