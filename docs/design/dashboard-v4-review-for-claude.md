## 建议布局

1. 顶部窄栏：当前会话/当前查看范围；运行状态；待处理数量；必要时连接状态。
2. 焦点区：一句工作标题 + 一句具体进度。优先级：需要用户动作 → 阻塞/失败 → 当前工作 → 完成结果。不要按每个日志片段不停切标题。
3. 紧凑因果阶段：准备请求 → 模型响应 → 执行工具 → 结果回填。当前高亮取自事件，不按计时器猜测。完整机制图按需展开，保留“模型生成 tool call，Agent 执行工具”的角色边界。
4. 活跃工具与子任务：每项一行，任务名、目标、状态、最后进度；行身份稳定，不按更新频率反复排序。已完成项目折叠，但错误/等待项不折叠。仅有一个工具时不造空列表。
5. 最近结果/事件：少量有意义的结果。日志在所选工具详情中；时间轴放“历史”，监督与回看不争主视觉。
6. 页脚资源：明确主/子会话、最近一次请求及统计口径。token/cost/缓存命中按需查看，未知就显示未知。

## 交互规则

- 子代理：宽屏可用详情侧栏，窄屏原位展开或整页下钻；两者都保留全局摘要和返回位置。离开后保持滚动、选中工具和历史位置。
- 运行状态与焦点选择正交：主流程等 explore 时 general 可以继续运行；不要把所有节点统一标暂停。
- 权限：以 permission 实体和 call/session ID 定位；在原有宿主/服务权限流程完成。实时等待才允许操作，历史回看仅展示当时记录；防止重放触发真实批准。
- 连接：断连显示“状态未知，最后同步 xx”，保留最后已知内容。没有新日志不等于卡死。取消先显示“已请求取消”，收到事实后才显示“已取消”。
- 回看：用“暂停跟随/返回实时”，不要把播放暂停与任务暂停共用一个图标。查看历史期间真实任务继续运行，显示新事件数量；回看不抢滚动。
- 动画：只辅助一次明确的状态转换；减少动画时保留静态方向、标签、状态。不循环制造“正在工作”的假信号。
- 可访问性：工具/子代理行用 button，Enter/Space 能展开；焦点可见；标题变化适度播报；颜色之外有文字/图标。420px 靠换行/布局切换，不靠裁剪解决。

## 数据契约先定，避免原型承诺超过数据

主检出核查发现现有类型是 TrajectoryRequest；RunModel 是拟议投影。请在自己的 worktree 复核，不把 main 的调查当成你当前分支已经实现。

- 请求级 usage 能画最近请求输入；无法证明输入中的 system、工具定义、历史各块精确 token 数。
- 运行中初始 token 为 0，不能解释为实际零消耗；需要 known/settled 标志。
- 现有历史没有完整逐 token 事件序列，不能生成看似实测的打字速度回放。已有数据可做步骤/最终文本回看。额外采集属于明确的新能力。
- 后台 task 工具 completed 可能只意味着启动成功；子代理实际生命周期必须看子 session/job，不能显示成已完成。
- retry、权限、连接健康、所选焦点、历史游标应分离，不能压成单一 running/done。
- 子代理最后文本不必然是“摘要”，不能保证固定 220 tok，也不能声称结束即销毁子上下文。
- 如需 RuntimeViewModel，至少区分事实来源、observedAt、连接健康、根/选中 session、请求阶段、待权限列表、活跃调用、子会话状态、usage 的 known/source，以及独立的 presentation 模式。不要新造 Agent 执行引擎。
