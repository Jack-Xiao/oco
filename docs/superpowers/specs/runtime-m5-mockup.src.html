怎么看这张图

  1. 中间的环 = 当前代理（第 1 轮 Sisyphus，之后 build）的一次循环：组装请求 → 模型思考 → 模型输出 → 调工具 → 等结果 → 带回结果，再发下一次请求。亮的站 = 此刻阶段，亮的弧 = 这次请求走到哪了。卡片上方一行是轮次 / 请求计数；会话里有过执行计划时，旁边多一个“计划 完成数/总数”。
  2. 环心卡片 = 此刻在发的东西：左上角是种类，后面是“谁 → 谁”，正文是原样摘录。代理写 / 更新执行计划时，卡片种类是“计划”，逐项照录内容和状态。点卡片看全文。
  3. 位置固定：左边是“你”，环上方是“模型”，右边是“工具台”和“子代理”。本轮还没派子代理时，子代理区收成一条（本轮情况 + 本会话共几个子代理），腾出的地方给环；派出第一个时展开。移动的小点就是正在路上的请求、调用、结果或提问；在哪里停着，哪里就在干活（工具停在那一行门口，子代理停在格子右上角）。子代理区：上沿派出 → 格子里作业 → 下沿回来 → 左下小点 = 做完等取回 → 取回。
  4. 点子代理看它此刻的状态：格子、路上 / 停着的小点、收起时那一条都能点（键盘 Tab + 回车也行）。详情盖在环上：名字和类型、状态（派发中 / 运行中 / 待取回 / 已取回 / 失败）和用时、交接内容、它自己的工具调用和文字、返回结果，以及“打开子会话”（跳转，不是操作）。收起那一条点开是本会话到此刻派过的全部子代理。Esc 或 ✕ 关闭；只用 ≤ 此刻的事件。
  5. 颜色：build 思考 运行 / 子代理 完成 失败 / 忽略 需要你

样稿的已知限制

  1. 第 1 轮的代理在导出里叫“Sisyphus - ultraworker”（第 2–4 轮是 build）。环和卡片的“谁 → 谁”只用名字的前半段“Sisyphus”，完整名字写在“你”卡片。
  2. todowrite 在“写参数”阶段没有逐字时间：计划卡片按这个调用的创建 → 开始时间等速逐项显现（同文本 / 推理的做法），开始之后才算有计划、才出现“计划 n/m”小标。
  3. 授权（permission）请求：设计上和提问共用“你”的位置和琥珀色，但这段会话是全放行，数据里没有授权事件，没有演示。
  4. 文本和推理没有逐字时间，样稿按部件起止时间等速显现前缀；导出里推理文本截断在 400 字。
  5. 面板很矮时（窄屏舞台不足约 470px、宽屏不足约 380px）舞台内部改为竖向滚动，字号不缩小。
  6. 移动的小点只是装饰：所有文字、计数、状态都直接由事件时间算出，和小点是否到达无关，所以不同宽度下事实一致。
  7. 进度条只画已经发生的刻度；≈ 折叠记号要等这段等待 / 空闲已经超过 10 秒才出现，t 之后是一条没有标记的轨道；但轨道全长和折叠比例来自整段记录，只有回放才有，实时模式没有这条轨道。
