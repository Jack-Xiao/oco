这是什么

侧栏最上面新增一个分区 Needs attention，把所有会话（包括子代理）里「在等人」的事情列成一张待办清单。你不用猜哪个会话卡住了，也不用逐个点开。

四种行

  • 权限：某个子代理想跑 bash、改文件、访问网络。行内直接 Allow / Always / Deny，对应上游 POST /permission/:id/reply。
  • 提问：agent 问你一个选择题。Answer 打开那个会话答题，Dismiss 直接拒答。
  • 报错：会话异常终止（限流、鉴权、崩溃），点开看。
  • 完成未读：跑完了你还没看过，沿用侧栏现有未读机制。

数据从哪来

没有新接口。session-feed 已经在收 /event SSE 和 /permission、/question 快照，收件箱只是同一份状态的另一种投影。批复从 Extension Host 直接发给服务端，不经过聊天 webview 的桥。

状态栏与通知

状态栏 🔔 计数 = 权限 + 提问行数。新请求出现且不是当前打开的会话时弹一条 VS Code 原生通知，点 Show 聚焦侧栏。同一时刻只保留一条。

试一下：批掉三条权限，看计数归零、子代理恢复 busy。

oco 不做

  • 不自己判断该不该允许，不建本地规则库。「Always」就是上游的 always，由服务端记。
  • 不做常驻弹窗、不出声音，不轮询。
  • 过期请求只提示「已处理」，绝不重发到别的请求上（按 requestId + sessionID 绑定）。

这是什么

两件事拼在一起：批量发起把一份任务清单变成 N 个并行跑的 OpenCode 会话；结果卡在它们跑完后给你一屏决策视图，决定哪些合并、哪些重跑、哪些扔掉。

批量发起

  • 输入是一个 JSON 清单：每项有提示词，可选 agent、模型、目录。
  • 命令 oco: Run batch… 弹确认面板，列出批次名、并发上限、默认 agent / 模型、连接。
  • 发起：逐项 POST /session + prompt_async，发后即忘。并发由 oco 在 Extension Host 内节流，队列只在内存 + memento。
  • 分组：侧栏多出一个 Batch 分区，按批次标签分组，这顺便落实了一直没做的 T009。
  • 宿主重启后未发起的项显示「待确认」，不自动续跑。

结果卡

每个会话一张卡：状态、agent / 模型、改动文件数、耗时、花费、最后一条输出，按钮「打开 diff」「打开会话」「重跑」「中止」。顶部是批次汇总。全部数据来自服务端消息和运行视图已有索引，oco 不重算。

试一下：点左边 ▶ oco: Run batch…，看并发 3 的节流、侧栏分组、结果卡逐张出现。其中一项会等权限、一项会失败。

oco 不做

  • 不做推理循环、不执行工具、不替你批权限（等权限的项会出现在第三步的收件箱）。
  • 不做定时器 / cron。夜间跑用一个 shell 脚本包 opencode run 交给 launchd，第二天早上在这里看结果卡。
  • 批次标签不写进服务端，换机器就没了。接受这个代价。
  • 发送失败不盲目重试：先查会话是否已创建，查不到标「结果未知」。

验收标准

清单 6 项、并发 3，任意时刻 busy ≤ 3；全部结束后侧栏按批次分组显示 6 个会话，结果卡与服务端数据一致。
